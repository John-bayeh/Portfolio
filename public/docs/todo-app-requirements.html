01

Project Overview

Most todo apps are throw-away exercises. This one is different. The same feature set — add, complete, filter, delete — is delivered through a fully containerized, multi-service architecture that mirrors how real production systems are built. The goal: demonstrate that software engineering fundamentals scale down as well as up.

Why Microservices?

  • ✦ Service isolation — Auth and Tasks have zero runtime coupling
  • ✦ API gateway pattern via Nginx — single public entry point
  • ✦ Docker Compose orchestration with health checks & named volumes
  • ✦ Independent deployability of each service

nginx/nginx.conf — Routing Rulesnginx
# Nginx API Gateway
upstream auth_service  { server auth-api:4000; }
upstream tasks_service { server tasks-api:4001; }

server {
  listen 80;
  location /api/auth/  { proxy_pass http://auth_service/;  proxy_set_header Host $host; }
  location /api/tasks/ { proxy_pass http://tasks_service/; proxy_set_header Host $host; }
  location / { root /usr/share/nginx/html; try_files $uri $uri/ /index.html; }
  location /health { return 200 "ok\n"; }
}
03

Functional Requirements

  • ✓
    User Registration & Login: Auth Service issues a signed JWT on successful login. bcrypt password hashing. Duplicate email rejected with 409.
  • ✓
    Authenticated Task CRUD: All task endpoints require a valid Bearer token. Tasks are user-scoped — each user sees only their own tasks.
  • ✓
    Optimistic UI Toggle: Clicking a task checkbox updates the UI instantly. If the PATCH request fails, UI reverts automatically — no stuck state.
  • ✓
    Filter: All / Active / Completed: Filter state preserved in URL query string — shareable and refresh-safe.
  • ✓
    Docker Compose Orchestration: docker compose up --build starts all 6 services with correct dependency order, health checks, and named volumes.
  • ✓
    Redis Session Validation: Tasks Service reads JWT validity from Redis. Cache miss triggers 401 — no PostgreSQL auth_db lookup on every request.
  • ✓
    PostgreSQL Persistence: Tasks and users survive container restarts via named Docker volumes. Two isolated schemas prevent cross-service coupling.
  • ✓
    Multi-Stage Dockerfiles: Builder stage installs devDependencies; runtime stage copies only production artifacts. Service images stay under 120 MB.

API Contracts

Auth Service — /api/auth

POST
/api/auth/register
Body: {email, password} → 201 {token, user} · 409 if email exists
POST
/api/auth/login
Body: {email, password} → 200 {token} · 401 on wrong credentials
POST
/api/auth/logout
Auth required. Invalidates JWT validity flag in Redis. → 200

Tasks Service — /api/tasks (Bearer token required)

GET
/api/tasks?filter=all|active|completed
Returns filtered task list for the authenticated user.
POST
/api/tasks
Body: {title} → 201 {id, title, done: false} · 400 if title is empty
PATCH
/api/tasks/:id/toggle
Flips task.done boolean. → 200 {id, done} · 404 if not found
DEL
/api/tasks/:id
Removes task from tasks_db. → 204 No Content
05

Technical Decisions

Microservices over MonolithArchitecture

Auth and Tasks are independent concerns. Isolating them allows each service to be scaled, updated, and deployed independently — no coupling between feature domains.

Nginx as API GatewaySecurity

Single public port (80) hides internal service topology. Nginx handles routing, static file serving, and provides a natural place for future rate limiting and SSL.

PostgreSQL over SQLiteReliability

Production-grade from day one. Two isolated schemas (auth_db, tasks_db) prevent accidental cross-service data access. Named Docker volumes survive restarts.

Redis for Token ValidationPerformance

Tasks Service validates JWT by checking Redis first. 94% cache hit rate at 500 VUs — PostgreSQL auth_db query count stays flat regardless of traffic spikes.

Multi-Stage Docker BuildsDevOps

Builder stage installs all devDependencies. Runtime stage copies only production artifacts. Result: service images under 120 MB with a reduced attack surface.

Optimistic UI ToggleUX

Task state updates instantly on click. The PATCH request happens in the background. On failure, UI reverts automatically — zero perceptible latency for the most common interaction.

Docker Compose Configuration

docker-compose.yml — Full Stack Orchestrationyaml
version: '3.9'

services:
  nginx:
    image: nginx:alpine
    ports: ['80:80']
    volumes:
      - ./nginx/nginx.conf:/etc/nginx/nginx.conf:ro
      - ./frontend/dist:/usr/share/nginx/html:ro
    depends_on: [auth-api, tasks-api]
    healthcheck:
      test: ["CMD", "wget", "-qO-", "http://localhost/health"]
      interval: 15s

  auth-api:
    build: ./services/auth
    environment:
      - DB_URL=postgres://postgres:secret@postgres:5432/auth_db
      - REDIS_URL=redis://redis:6379
      - JWT_SECRET=${JWT_SECRET}
    depends_on: [postgres, redis]

  tasks-api:
    build: ./services/tasks
    environment:
      - DB_URL=postgres://postgres:secret@postgres:5432/tasks_db
      - REDIS_URL=redis://redis:6379
      - JWT_SECRET=${JWT_SECRET}
    depends_on: [postgres, redis]

  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_PASSWORD: secret
    volumes:
      - pgdata:/var/lib/postgresql/data

  redis:
    image: redis:7-alpine
    command: redis-server --appendonly yes
    volumes:
      - redisdata:/data

volumes:
  pgdata:
  redisdata:
services/tasks/Dockerfile — Multi-Stage Builddockerfile
# Stage 1: Builder
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev
COPY . .

# Stage 2: Lean runtime image
FROM node:20-alpine AS runtime
WORKDIR /app
COPY --from=builder /app/node_modules ./node_modules
COPY --from=builder /app .
EXPOSE 4001
HEALTHCHECK --interval=15s --timeout=5s \
  CMD wget -qO- http://localhost:4001/health || exit 1
CMD ["node", "src/index.js"]
