SPECIFICATION v1.0

Telegram Award Voting Platform

Product Requirements Document (PRD) for Community Award Campaigns

Client/Target Telegram Communities
Architecture React SPA · Node.js · MongoDB
Security Focus Zero-Auth Deduplication

1. System Overview

The Telegram Award Voting Platform is a fast, lightweight web application designed to host public award voting campaigns for Telegram channels and group communities. Administrators define categories (e.g., "Most Helpful Member", "Top Developer") and nominate community members. Users visit the site to cast votes for their favorite nominees.

A key constraint is the frictionless voting requirement: users must be able to vote with a single click without the hurdle of creating accounts, logging in via Telegram, or verifying phone numbers. To support this while maintaining campaign integrity, the backend employs a Zero-Auth Anti-Fraud Engine combining client device fingerprinting and IP tracking.

2. User Roles & Use Cases

2.1 End User (Voter)

  • Browse Nominees: View categories, nominees' details (Telegram username, profile tag), and real-time vote metrics.
  • Cast Vote: Select a nominee in a category and vote. The vote must register instantly without requiring account creation.
  • View Current Standings: See live updates of nominee rankings once they have voted (or if the category is closed).

2.2 Admin (Channel Owner)

  • Category Management: Create, edit, and delete award categories (with start/end dates).
  • Nomination Management: Nominate handles with custom bios and images.
  • Campaign Dashboard: View vote logs, inspect fraud markers, reset anomalous categories, and open/close voting windows manually.

3. Functional Requirements

3.1 Dynamic Category Landing

The home page presents active categories in a tabbed layout. When a category is active, it displays a card list of nominees in randomized positions (to prevent left-to-right bias).

3.2 Zero-Auth Anti-Fraud Engine

To prevent automated voting scripts and click-farms without forcing users to sign in, the system enforces a strict verification schema:

Deduplication Logic

Each vote payload submitted to POST /api/vote requires a fingerprint parameter generated on the client-side. The backend stores the combined unique signature:

UniqueKey = Hash(CategoryID + ClientFingerprint + VoterIP)

If a record with this key already exists in MongoDB, the vote is blocked with an HTTP 429 Status.

Feature ID Requirement Description Acceptance Criteria
FR-01 Deduplication Checks Verifies that the incoming voter fingerprint hasn't already voted in the requested category.
FR-02 Rate Limiting Limits requests per IP (max 5 votes/min) to prevent brute-force API flood attempts.
FR-03 Admin Authentication Admin panel actions require a secure session token validated in Express headers.
FR-04 Real-time Counter Sync Nominee cards refresh vote tallies dynamically using Server-Sent Events or polling.

4. Data Schema (MongoDB)

MongoDB is selected for schema flexibility (allowing nominees to have dynamic Telegram metadata, user tags, or bios). 

// 1. Nominee Schema
const NomineeSchema = new Schema({
  name: { type: String, required: true },
  telegramHandle: { type: String, required: true },
  avatarUrl: String,
  bio: String,
  votes: { type: Number, default: 0 },
  categoryId: { type: Schema.Types.ObjectId, ref: 'Category', index: true }
});

// 2. VoteLog Schema (Enforces Deduplication)
const VoteLogSchema = new Schema({
  categoryId: { type: Schema.Types.ObjectId, ref: 'Category', required: true },
  fingerprint: { type: String, required: true },
  ipHash: { type: String, required: true },
  timestamp: { type: Date, default: Date.now }
});

// Compound unique index prevents race conditions/duplicate writes in MongoDB
VoteLogSchema.index({ categoryId: 1, fingerprint: 1 }, { unique: true });
VoteLogSchema.index({ categoryId: 1, ipHash: 1 }, { unique: true });

5. Non-Functional Requirements

5.1 Performance Under Spike Loads

  • When a Telegram channel broadcasts the voting URL to 20,000+ members simultaneously, the database must not lock.
  • Solution: Express uses MongoDB atomic increments ($inc) on the nominee records to avoid transactional database locks. Memory-level caching is deployed on active counter routes.

5.2 Accessibility & Responsive Layout

  • The voting experience must be fully optimized for mobile devices because 90%+ of Telegram users open links inside the internal Telegram in-app browser.
  • Clean, lightweight CSS is used with no bulky frameworks, achieving a Mobile performance score of >95 in audits.
