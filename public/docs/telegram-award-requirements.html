1. System Overview

The Telegram Award Voting Platform is an enterprise-grade, high-scale web system designed to handle fast-spike public voting campaigns within major Telegram communities. The platform allows channel owners to nominate members across custom categories, generating massive waves of traffic (often exceeding 20,000 simultaneous users) when broadcasted via Telegram channel posts.

To eliminate user friction, the platform requires Zero-Auth single-click voting (no Telegram login, email verification, or passwords). The requirements call for a system architecture capable of guaranteeing data integrity, resisting professional click-farms, and avoiding database write locks under heavy concurrent bursts, while delivering localized client experiences globally.

2. High-Scale & Security Engineering

2.1 Redis write Buffering (Scale Architecture)

Under high concurrency, writing every vote immediately to MongoDB leads to transaction timeouts and database connection exhausts. The platform utilizes an **in-memory Redis buffer**:

  • Atomic Queuing: When a user votes, the API increments the vote count inside Redis immediately via fast HINCRBY operations (processing in <2ms).
  • Batch Synchronization: A background daemon flushes aggregated vote logs from Redis to MongoDB in micro-batches every 10 seconds, offloading database load by 98%.

2.2 Advanced Anti-Sybil (Behavior & Hardware Heuristics)

Without login walls, malicious actors will attempt to automate voting. The system prevents fraud through a layered security stack:

  • Client Hardware Fingerprinting: Combines HTML5 Canvas rendering anomalies, WebGL GPU driver identifiers, and Audio Context frequencies to compile a hardware signature unique to the physical device.
  • Behavior Analysis: Tracks cursor movement paths, typing intervals, and time-to-vote parameters. Headless scrapers (Puppeteer, Selenium) are flagged and blocked instantly.
  • Proxy/VPN Detection: Cross-references IP addresses against a live database of commercial hosting ranges and public VPN lists, prompting a CAPTCHA fallback for flagged addresses.

2.3 Cryptographic Trust & Verifiability (Public Ledger)

To ensure transparency and eliminate accusations of admin data manipulation, votes are signed and chained:

Public Verification Audit

Each vote is cryptographically linked to the previous vote hash using a Merkle Tree structure. The root hash of the tree is published at the end of each hour. Voters receive a receipt token that allows them to run a client-side verification script to verify that their specific vote is mathematically included in the final tallies.

3. Global Delivery & Localization

Telegram users are spread across multiple continents. To provide a seamless experience:

  • Dynamic Edge Routing: The static React client is cached globally on edge CDN nodes (Netlify Edge). Middleware detects user geography and serves localized assets under 50ms.
  • Multi-language (i18n): The client fully translates templates dynamically into English, Russian, Amharic, Arabic, and Spanish, aligning with major Telegram demographics.

4. Data Schema & Storage Architecture

MongoDB houses persistent nominee records and voting summaries, while Redis manages live transaction logs. 

// MongoDB Nominee Schema
const NomineeSchema = new Schema({
  name: { type: String, required: true },
  telegramHandle: { type: String, required: true },
  avatarUrl: String,
  votes: { type: Number, default: 0 },
  categoryId: { type: Schema.Types.ObjectId, ref: 'Category', index: true }
});

// MongoDB Audit Log Schema (Chained blocks for public auditing)
const AuditLogSchema = new Schema({
  voteIndex: { type: Number, unique: true, index: true },
  nomineeId: { type: Schema.Types.ObjectId, required: true },
  previousHash: { type: String, required: true },
  currentHash: { type: String, required: true, unique: true },
  timestamp: { type: Date, default: Date.now }
});

5. Non-Functional Requirements

5.1 Scalability & Availability

  • Must maintain 99.99% availability during peak marketing campaigns.
  • Recovery Time Objective (RTO): < 5 minutes; automatic database replication failover on MongoDB Atlas multi-region clusters.

5.2 Mobile Optimization (In-App Browser Compliance)

  • Must compile to a lightweight JS bundle (<120KB gzipped) to load efficiently inside the Telegram in-app mobile webview.
  • A11y compliant with support for screen readers, high contrast, and touch targets >48px.
