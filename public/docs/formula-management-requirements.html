Formula Management System

A configurable, audit-ready platform that replaces spreadsheet-based resource allocation with rule-driven formula engines, corridor monitoring, Gantt scheduling, and structured concept-to-feasibility workflows — fully integrated with the existing Project Management System (PMS).

01

System Overview

The Formula Management System sits as a governance layer above the existing PMS. It introduces six modules — Formula Engine, Corridor Engine, Schedule Matrix, Concept Administration, Feasibility Administration, and a Common Layer — without modifying the existing PMS database or codebase. Integration is non-destructive: the system reads from and writes back through defined interfaces only.

PHASE 1
Weeks 1–2: Technical Assessment
Full technical assessment of existing PMS API, database schema, and data model.
NON-DESTRUCTIVE
Zero PMS Changes
No changes to existing PMS database schema or codebase.
API-FIRST
REST or ETL Fallback
Connect in real time via REST endpoints; ETL pipeline fallback if no API available.
BI-DIRECTIONAL
Allocation Write-Back
Allocation outputs written back to PMS so project officers see results in their existing interface.

Module 1: Project Allocation & Formula Management

Automates resource, budget, and priority allocation through configurable formulas — replacing manual spreadsheet-based allocation with a transparent, auditable, rule-driven system.

IDRequirementPriority
FR-01 Formula Configuration Interface — admins define allocation formulas using configurable parameters (budget ceiling, project capacity, priority level, risk score, geographic weight, resource availability). No code change when rules change. HIGH
FR-02 Dynamic Calculation Engine — calculates allocation values in real time when parameters are updated. Supports complex multi-parameter formulas with weighted scoring. HIGH
FR-03 Version Control for Formulas — each formula version saved. Historical allocations reference the formula version that produced them. HIGH
FR-04 Allocation Audit Trail — every allocation result is traceable (formula, parameters, calculated value, approving official). Non-editable record. HIGH
FR-05 Override Workflow — authorized officials apply manual overrides with mandatory documented justification. Override carries approving official identity, timestamp, and reason. HIGH
FR-06 PMS Integration — reads project data directly from existing PMS. Allocation outputs written back in real time. HIGH
FR-07 Reporting — allocation comparison across projects, time periods, and administrative units. Export to PDF and Excel. MEDIUM
04

Module 2: Corridor Management

Defines and enforces operational boundary frameworks — acceptable ranges for key project parameters — to ensure projects remain within approved governance limits throughout execution.

IDRequirementPriority
FR-08 Corridor Definition — define corridors with min, max, and threshold values for budget range, duration, staffing levels, geographic coverage, risk score. Separate profiles per project type/region. HIGH
FR-09 Project-Corridor Assignment — assign projects to corridor profiles based on type, scale, location. Assignments logged and auditable. HIGH
FR-10 Real-Time Compliance Monitoring — continuous monitoring of all active projects against corridor boundaries. Regional dashboard shows every project's status. HIGH
FR-11 Threshold Alert System — automatic alerts when projects approach (warning) or exceed (breach) corridor limits. Alerts routed to responsible official with required response time. HIGH
FR-12 Corridor Data in Schedule Matrix — corridor boundaries visible in the schedule matrix view. Scheduling decisions constrained by corridor definitions. MEDIUM
05

Module 3: Schedule Matrix & Forecasting

Provides integrated scheduling visualization and data-driven forecasting based on current PMS data and historical performance from 4,000+ encoded projects.

IDRequirementPriority
FR-13 Schedule Matrix View — visual matrix of all projects by administrative unit, time period, and resource allocation. Filterable by zone, woreda, project type, and status. Color-coded compliance indicators. HIGH
FR-14 Gantt Timeline View — project timelines in Gantt format. Overlapping schedules and resource conflicts highlighted automatically. Critical path identification. HIGH
FR-15 Forecasting Engine — uses 4,000+ historical project records to generate completion probability forecasts for active projects. Forecasts updated as new data arrives. Confidence intervals shown. HIGH
FR-16 Scenario Modeling — create what-if scenarios by adjusting resource allocations, timeline parameters, or budget inputs. Compare projected outcomes side by side. MEDIUM
FR-17 Resource Conflict Detection — identifies projects competing for the same resources at the same time. Suggests resolution options. HIGH
FR-18 PMS Synchronization — schedule data reflects PMS project statuses in real time. HIGH
06

Module 4: Project Concept Administration

Replaces paper files, email chains, and scattered documents with a structured digital system for managing project ideas from concept submission to approval decision.

IDRequirementPriority
FR-19 Digital Concept Submission — structured online form (project title, objective, estimated cost, beneficiary population, implementing body, timeline, supporting document uploads). HIGH
FR-20 Evaluation & Scoring Rubrics — configurable scoring criteria applied by evaluators. Multi-criteria scoring aggregated automatically. Evaluators cannot see each other's scores before submission. HIGH
FR-21 Three-Stage Approval Workflow — Reviewer → Committee → Management. Each stage requires documented approval or rejection with reason. Notifications sent at every transition. HIGH
FR-22 Status Transparency — submitting body sees real-time status (Draft, Submitted, Under Review, Approved, Rejected). HIGH
FR-23 Concept Archive — approved concepts archived and searchable for future implementation reference. MEDIUM
FR-24 Analytics Dashboard — concept pipeline by stage, approval rates, average review time, submission trends by organization. MEDIUM
07

Module 5: Feasibility Study Administration

Automates the planning, assignment, evaluation, and approval of project feasibility studies — replacing manual Word/Excel-based processes with a structured, traceable system.

IDRequirementPriority
FR-25 Feasibility Study Registration — digital registration with project information, study type (Technical, Financial, Legal, Operational, Environmental), requesting body, required timeline. HIGH
FR-26 Evaluator Assignment & Workload Management — assign qualified evaluators per study. Track workload and availability. Prevent over-assignment. HIGH
FR-27 Standardized Scoring — apply defined criteria per feasibility category. System generates recommendation outputs based on scoring thresholds. Manual override available with documentation. HIGH
FR-28 Approval Workflow — Reviewer → Committee → Management chain. Explicit sign-off required at each stage. Escalation triggers if response time exceeded. HIGH
FR-29 Document Versioning — upload, store, and archive all feasibility documents. Full version history maintained. Documents linked to PMS project records. HIGH
FR-30 Audit Trail & Reporting — full record of who reviewed what, when, and with what outcome. Non-editable. Feasibility pipeline dashboards for management. HIGH
